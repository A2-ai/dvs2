# Rebase campaign — lessons log

Goal: rebase every open PR onto current `origin/main`, one at a time, force-with-lease push, do NOT merge.
After each agent completes, append what was learned here and feed it into the next agent.

## Seeded gotchas (from project memory)
- rpkg generated files (NAMESPACE, R/*.R wrappers, man/*.Rd, src/rust/lib.rs, Cargo.lock): on conflict, REGENERATE, do not hand-merge. Sequence: `just rpkg-update → rpkg-configure → rpkg-install → rpkg-document` (never skip rpkg-document).
- rpkg R build needs R 4.5 (rig default reverts to 4.6). Prefix just recipes with the 4.5 Rscript PATH and `rv sync` first.
- Use justfile recipes, not raw cargo/tar/Rscript.
- dvs core crate must have NO miniextendr deps.
- Never `git push --force`; always `--force-with-lease`.
- Stacked PRs: rebase onto the (already-rebased) PARENT branch, not main directly, so the PR diff stays minimal.
- No em-dashes/semicolons in specs.md or project files.

## Accumulated lessons (feed into every subsequent agent)
- **R 4.5 PATH**: `/Library/Frameworks/R.framework/Versions/4.5-arm64/Resources/bin`. Prefix just recipes with `export PATH="/Library/Frameworks/R.framework/Versions/4.5-arm64/Resources/bin:$PATH"`. rig default is 4.6; the framework dir exists locally.
- **Skip `rv sync` from repo root** — it needs rproject.toml in a separate dev-test project. Not needed for the scaffold sequence.
- **Generated-file conflicts: do NOT blind `git checkout --theirs`.** `--theirs` is the stale PR side and silently drops feature work that landed on main since the branch forked (it dropped #203/#204 recursive API). Robust pattern: `git checkout origin/main -- <file>`, inspect PR's own edits with `git show <pr-sha> -- <file>`, re-apply only those, confirm with `git diff origin/main -- <file>` that the result is the intended (e.g. scaffold-only) diff.
- **rpkg `dvs` dep is a GIT pin (branch=main from A2-ai/dvs2), not a path.** `just rpkg-update` bumps the pin to current main HEAD, so a rebase surfaces dvs core API drift at COMPILE even when no .rs file conflicted. Check `dvs-cli/src/main.rs` call sites for the intended API. Drift seen on current main: `StatusFilter`→`PathFilter`; `get_status` gained 3rd arg `Option<&str> glob`; `resolve_paths_for_get` gained 4th arg `bool recursive`.
- **Verify rpkg with `just rpkg-document`** (devtools, temp lib, respects .libPaths) and `cargo build --manifest-path=dvs-rpkg/src/rust/Cargo.toml --release`. The `just rpkg-install` failure `no package called 'cli'` is a LOCAL install-subprocess libpath quirk, NOT a code blocker — wrappers regenerate during compile (cdylib load) before that failure, so they're valid. Confirm wrappers with `git diff <pr-sha> -- dvs-rpkg/R/dvs-wrappers.R`.
- Scaffold sequence that worked: `just rpkg-update` (Cargo.lock/pin) → `just rpkg-configure` → `just rpkg-document` (regenerates wrappers + man). `rpkg-install` optional given the quirk above.
- **CRITICAL (corrects the above): for a NON-rescaffold rpkg PR, do NOT run bare `just rpkg-update`.** Cargo.toml has FLOATING git deps for BOTH dvs AND miniextendr. Bare update bumps miniextendr (68b6b207 → baf9ba86) which removes/renames APIs (`miniextendr_api::ffi`, `serde::ColumnarDataFrame`, `AsSerializeRow`) → E0432 build breaks. Bumping miniextendr is the dedicated job of the #207 rescaffold PR, not a rebase side effect. Correct recipe for everyone except #207: `git checkout origin/main -- dvs-rpkg/src/rust/Cargo.lock && just rpkg-update --package dvs`. This advances ONLY the dvs pin to current main HEAD; Cargo.lock diff vs main = single line (dvs rev). Verify miniextendr stayed pinned: `grep -A2 'name = "miniextendr-api"' dvs-rpkg/src/rust/Cargo.lock | grep source` must still show 68b6b207.
- For generated `dvs-wrappers.R` conflicts that are ONLY `(lib.rs:NNN)` line-number shifts: `--theirs` to unblock is safe BECAUSE you immediately regenerate with `just rpkg-document`; line numbers then reflect the rebased lib.rs. Always run rpkg-document post-rebase and fold the result into the rpkg commit (fixup+autosquash).
- lib.rs conflict pattern: when main adds a guard/early-return before a call and the PR changed that same call, keep BOTH sides — do not pick one wholesale.
- macOS ld warnings ("object file built for newer macOS 26.5 than 26.0") during rpkg-document are noise, not errors.
- **miniextendr-pin nuance**: "never bump miniextendr" has an exception — a PR may legitimately need a symbol. CHECK if main's pin already has it before assuming a bump is required: `git -C <miniextendr-worktree> grep <symbol> 68b6b207`. (e.g. 68b6b207 already exports `vec_to_dataframe_split`, `ColumnarDataFrame`, `AsSerializeRow`.) If present, keep main's pin and override the PR's bump.
- **rpkg builds against the GIT-PINNED dvs, not the local `dvs/` worktree.** A local dvs core change (e.g. paths.rs) is invisible to the rpkg build unless you add the documented uncommitted `[patch]` block pointing at `../../../dvs`, build, then REVERT it before committing. The branch is correct as committed but only functions end-to-end once its dvs commit lands on main and the pin is bumped (`just rpkg-update -p dvs`).
- **Watch for SEMANTIC overlap, not just textual conflicts**: main may have independently implemented the same feature a different way. Preserve the PR's distinct design and FLAG the overlap for the reviewer.
- A "bypass resolve_paths when no glob" optimization is only safe with non-empty explicit paths — empty paths trigger cwd-scoping which lives in resolve_paths_*. Add `!paths.is_empty()` to any such bypass.
- **STACKED PRs**: rebase the child onto the PARENT's NEW tip with `git rebase --onto <new-parent-tip> <old-parent-tip> <child-branch>`, NOT onto main directly — keeps the PR diff minimal. A stacked rpkg child inherits its parent's miniextendr pin (e.g. #223 builds against #207's baf9ba86, NOT main's 68b6b207).
- **Re-grep BOTH pins AFTER `just rpkg-document`, not only after rebase.** rpkg-document re-resolves Cargo.lock and will SILENTLY drop a git pin back to `registry+crates.io`. Restore with `git checkout dvs-rpkg/src/rust/Cargo.lock` (the rebase already brought the correct pin).
- **main's Cargo.lock dvs pin LAGS main HEAD** (frozen at ea5e6901 even though main HEAD is 8288f85). "Advance dvs pin to current main HEAD" can be a no-op. Compare against main's *lock* dvs pin, not main HEAD sha.
- **Redundant-overlap commit**: when a PR commit duplicates something already merged to main/parent (e.g. #211's jiff change), the substantive change is already there and only a doc comment may differ — `git rebase --skip` it, don't salvage.
- **Doc/spec PRs: grep the actual clap arg defs on origin/main**, don't just resolve text conflicts. Decisive check e.g. `grep -n "Status {" -A12 dvs-cli/src/main.rs` on origin/main. A clean textual rebase can mask a doc that contradicts current code.
- **ALWAYS reset the worktree to `origin/<branch>` before rebasing.** Local PR worktree checkouts can be STALE (behind the real PR tip) — rebasing the stale state replays the wrong content. `git fetch origin && git reset --hard origin/<branch>` first.
- **No-upstream worktree push**: a bare `git push --force-with-lease` fails with "no upstream branch" on worktrees with no tracking set. Use explicit refspec: `git push --force-with-lease=<branch>:<old-sha> origin <branch>:<branch>` (keeps lease protection).
- **Stacked base merged AND refactored before merge**: `git rebase` won't auto-detect the lower commits as empty (main's version diverged). Cleanest: `git reset --hard origin/main` then cherry-pick ONLY the unique top commit(s) — works when the unique commit touches files that don't overlap the merged base.
